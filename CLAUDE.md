# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

**SimpleMeet** — ระบบประชุมออนไลน์สถานศึกษา (Thai-language online meeting management system for educational institutions). The app serves a public agenda page (no login required) and an admin interface for managing meetings and users.

- **URL**: `http://localhost/rvc.meet/meet/` (XAMPP)
- **First-time setup**: navigate to `http://localhost/rvc.meet/meet/install.php`

## Stack

| Layer | Technology |
|-------|-----------|
| Backend | PHP 8.0+, no framework |
| Database | MariaDB 10.x, UTF-8mb4, all datetimes in UTC |
| Frontend | React 18 (UMD) + Babel standalone — **no build step** |
| Fonts | Google Fonts: Anuphan (display), Sarabun (body) |

## Development commands

No build tooling exists. The workflow is:

```bash
# PHP syntax check a file
php -l meet/api/some_file.php

# Syntax check all PHP API files at once
for f in meet/api/*.php meet/install.php; do php -l $f; done

# Verify DB connection manually (XAMPP)
php -r "new PDO('mysql:host=localhost;dbname=simplemeet', 'root', '');"
```

Frontend changes are live immediately — just reload the browser. PHP changes are also live (no restart needed in XAMPP).

## Architecture

### Request flow

```
Browser → meet/index.html
            ├── loads 6 JSX files as <script type="text/babel"> (in order)
            └── React app calls meet/api/*.php via fetch()

Browser → meet/api/meetings.php  (REST: GET/POST/PUT/DELETE)
         meet/api/auth.php        (GET=session check / POST=login / DELETE=logout)
         meet/api/users.php       (CRUD, admin-only)
            └── all require meet/api/config.php
```

### JSX load order matters

`index.html` loads scripts sequentially. Each file exports to `window.*` and the next file consumes those globals — **order cannot be changed**:

1. `icons.jsx` → exports all `Ico*`, `Pf*`, `PLATFORMS` to `window`
2. `data.jsx` → exports time helpers, `meetingStatus`, `countdownTo`, `DEPARTMENTS`, `uid` to `window`
3. `components.jsx` → exports `MeetingCard`, `JoinLink`, `StatusPill`, `useNow`, etc. Defines `READY_MS = 15 * 60 * 1000`
4. `views_public.jsx` → exports `PublicAgenda`, `MeetingDetail`
5. `views_admin.jsx` → exports `Login`, `Dashboard`, `MeetingForm`, `Calendar`, `UserManagement`, `PERM_LABEL`
6. `app.jsx` → mounts React root; consumes everything above

### PHP API conventions

All API files follow the same pattern:
- `require_once __DIR__ . '/config.php'` first
- `header('Content-Type: application/json; charset=utf-8')`
- Use `jsonOk($data)` / `jsonError($message, $code)` — both call `exit`
- Use `requireRole(['admin', 'organizer'])` for write operations; `requireRole(['admin'])` for user management
- All datetimes: store as UTC via `isoToUtc($iso)`, return as ISO 8601 via `DateTimeInterface::ATOM`
- `api/db.config.php` is auto-generated by `install.php` and gitignored — never commit it

Response envelope:
```json
{ "success": true,  "data": ... }
{ "success": false, "error": "message" }
```

### Auth and permissions

Session-based. `$_SESSION['user']` contains: `id`, `username`, `name`, `role`, `permission`.

| permission | can do |
|------------|--------|
| `admin` | all — including user management (`/api/users.php`) |
| `organizer` | meeting CRUD only |
| `staff` | view agenda + calendar, click join links (authenticated) |

`auth.php` runs `ensurePermissionColumn()` on every login to auto-migrate older installs that lack the `permission` column.

### Meeting link states

Controlled entirely in `JoinLink` (components.jsx) using `meetingStatus()` + `READY_MS`:

| condition | appearance |
|-----------|-----------|
| `expired` (> 1 hr after end) | hidden |
| `ended` | grey, disabled |
| `upcoming` > 15 min | grey, disabled |
| `upcoming` ≤ 15 min (`isReady`) | **blue** "เตรียมเข้าห้องประชุม" |
| `live` | **green** "เข้าร่วมประชุม" |

Unauthenticated users who click an active link (ready/live) are redirected to login via `onLoginRequired` callback.

### Database

Three tables: `users`, `meetings`, `attachments`. Full schema in `meet/db/schema.sql`.

- `meetings.id` is a client-generated random string (`uid()` in JSX); server accepts it on POST
- `attachments` rows cascade-delete when a meeting is deleted
- `meetings.start_time` / `end_time` stored in UTC; the `idx_start` index is used for ordering

### CSS design system

All design tokens are in `:root` in `styles.css`. Key variables: `--blue`, `--green`, `--red`, `--purple`, `--font-display` (Anuphan), `--font-body` (Sarabun). Component classes: `.mcard` (meeting card), `.join` / `.join-live` / `.join-ready` / `.join-disabled` (link button states), `.st` / `.st-live` / `.st-upcoming` / `.st-ended` (status pills).

## Key files to know before editing

| File | Why it matters |
|------|---------------|
| `api/config.php` | All PHP helpers live here — `getDB()`, `requireRole()`, `jsonOk()`, `formatMeeting()`, `isoToUtc()` |
| `components.jsx` | `JoinLink` and `StatusPill` implement the core link-state logic; `MeetingCard` is used on every listing page |
| `app.jsx` | All React state lives here; permission guards, routing (`view` state string), CRUD async calls |
| `install.php` | Self-contained installer — creates DB, tables, admin user, seed data; also handles upgrades via `ADD COLUMN IF NOT EXISTS` |
